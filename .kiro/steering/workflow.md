# 작업 규칙

## 브랜치
- 지금 작업 브랜치는 **`feature/crowd-report-post`**예요 (커뮤니티 개편: 혼잡도 제보 + 한 줄 글 → 커뮤니티에 함께 올리기). 이 작업은 여기에 커밋하고 push해요.
- `main`에 직접 커밋하지 않아요. PR은 `main`으로 보내요.
- 다음 작업(사진 업로드, 심사 필수 항목 등)을 시작할 때는 새 브랜치를 만들지 사용자에게 먼저 물어봐요.
- PR은 **일반 머지(merge commit)**로 합쳐요. PR 설명의 되돌리기 명령이 커밋 번호를 쓰기 때문에, 커밋을 합치는 방식(squash)은 쓰지 않아요.

## 커밋과 PR
- 커밋 메시지는 한국어로, `영역: 변경 내용` 형식이에요 (예: `마이 탭 9차: 톱니바퀴 · 설정에서 버전 빼기`).
- 항목마다 커밋을 나눠서 하나씩 되돌릴 수 있게 해요.
- PR 설명은 PR #5 형식을 따라요: 요약 · 바뀐 것 · 병합 전에 확인해 주세요(실기기 체크리스트) · 여기서 확인한 것 · 되돌리기 · 이번에 안 한 것.

## 확인
- 이 샌드박스는 Linux라서 Xcode 빌드와 실기기 테스트를 할 수 없어요. `swiftc -parse`로 문법만 확인하고, 빌드와 실기기 확인은 PR 체크리스트로 사용자에게 부탁해요.
- Firestore 보안 규칙을 바꾸면 `npm run test:rules` 테스트도 같이 고쳐요.
